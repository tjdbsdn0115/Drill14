# 새 편대의 비행 애니메이션 설계

## 1. 실제 이미지의 포즈 경계를 먼저 확인

`bird_animation.png`의 크기는 918 × 506px입니다. 위에서 아래로, 각 행의 왼쪽에서 오른쪽으로
포즈가 이어집니다. 첫째 행 5개, 둘째 행 5개, 셋째 행 4개로 총 14개이며 마지막 칸은 비어 있습니다.

이미지 전체를 5 × 3으로 등분하면 가로 183.6px, 세로 약 168.67px이 됩니다.
하지만 픽셀 경계로 확인한 실제 포즈 간격은 **가로 182px, 세로 170px**입니다.
예를 들어 첫 행 마지막 포즈의 왼쪽 날개는 x=728부터 시작합니다.
가로를 183px로 자르면 이전 칸에 이 날개 일부가 섞이므로 정확한 간격이 필요합니다.
오른쪽의 8px 여백은 사용하지 않습니다.

프레임 번호 `i`를 정수로 바꾸고 14로 나눈 나머지를 사용합니다.

```text
column = i % 5
row = i // 5
left = column * 182
top = row * 170
height = min(170, image_height - top)
bottom = image_height - top - height
```

PNG의 행은 위에서 아래로 세지만, pico2d 클립 인자는 아래쪽을 기준으로 받습니다.
따라서 `bottom` 변환을 거쳐 0번 포즈부터 올바른 순서로 읽습니다.
각 행 첫 포즈의 클립은 다음과 같습니다.

| 포즈 | left | bottom | width | height |
| --- | --- | --- | --- | --- |
| 0 | 0 | 336 | 182 | 170 |
| 5 | 0 | 166 | 182 | 170 |
| 10 | 0 | 0 | 182 | 166 |

마지막 행은 높이가 166px입니다. 이미지 밖을 읽지 않도록 높이를 줄이되,
출력 크기도 같은 축척으로 줄이고 출력 중심을 `(170 - 166) * scale / 2`만큼 위로 이동합니다.
이렇게 하면 모든 행의 사각 영역 위쪽이 같은 기준에 놓입니다.
원본에 그려진 몸의 자연스러운 상하 움직임은 그대로 유지합니다.

## 2. 프레임 수가 아닌 경과 시간으로 날갯짓 계산

날갯짓 한 주기는 14프레임이고, 초당 두 주기를 재생합니다.

```text
frames_per_second = 14 * 2 = 28
frame = (frame + 28 * dt) % 14
```

`frame`은 실수로 누적하고 그릴 때만 정수로 바꿉니다.
매 갱신마다 정수로 바꾸면 높은 FPS에서 작은 증가분이 사라질 수 있기 때문입니다.
30 FPS에서는 한 번 갱신할 때 약 0.933프레임, 144 FPS에서는 약 0.194프레임 증가합니다.
모두 0.5초가 지나면 정확히 한 주기를 진행합니다.

10마리의 초기 위상은 `index * 14 / 10`입니다.
동일한 속도로 날아도 날개 모양이 완전히 일치하지 않아 편대가 자연스럽게 보입니다.
원본 애니메이션 자체에 몸의 상하 움직임이 있으므로 별도의 큰 사인 곡선 흔들림은 더하지 않았습니다.

## 3. 이동 속도를 실제 시간에 연결

boy와 같은 `10px / 0.3m` 축척을 사용합니다.

```text
speed = 30km/h * 1000 / 3600 * (10 / 0.3)
      ≈ 277.7778px/s
distance = speed * dt
```

게임 루프는 `time.perf_counter()`로 현재 갱신에 사용할 `dt`를 먼저 계산합니다.
이 시계는 시스템 시각 변경의 영향을 받지 않습니다.
매 프레임 콘솔 출력은 제거했고, 메인 캔버스는 수직 동기화를 요청합니다.
날갯짓과 이동은 수직 동기화 여부와 관계없이 같은 `dt`를 사용합니다.

## 4. 경계에서 초과 거리를 버리지 않고 반사

오른쪽 끝을 넘었다고 위치를 단순히 끝점으로 고정하면 그 프레임의 초과 거리가 사라집니다.
FPS가 낮아질수록 실제 이동 속도가 달라지는 문제가 생기므로 왕복 경로를 길이 `2 * span`의 순환 위상으로 표현합니다.

```text
span = right - left
phase = x - left                         # 오른쪽 비행
phase = 2 * span - (x - left)            # 왼쪽 비행
phase = (phase + distance) % (2 * span)

phase < span:  x = left + phase, direction = +1
그 외:        x = right - (phase - span), direction = -1
```

0~100 구간에서 x=90의 새가 오른쪽으로 25px 이동하면 결과는 x=85, 왼쪽 방향입니다.
한 갱신이 여러 번의 왕복 시간을 포함해도 나머지 연산 한 번으로 처리합니다.
오른쪽 경계에 정확히 도착하면 왼쪽, 왼쪽 경계에 정확히 도착하면 오른쪽을 향합니다.
이동 구간이 0이면 그 위치를 유지합니다.

그릴 때 방향이 음수인 경우에만 pico2d의 `'h'` 옵션을 사용합니다.
날갯짓 포즈 순서는 계속 0~13으로 진행하므로 왼쪽으로 돌아도 날갯짓 시간이 거꾸로 흐르지 않습니다.

## 5. 10마리가 편대를 유지하는 이유

5개 열의 중심은 편대 중심에서 -260, -130, 0, 130, 260px 떨어져 있습니다.
새의 출력 너비는 70px이므로, 1600px 캔버스에서 편대 중심의 이동 범위는 295~1305px입니다.

각 새의 초기 위치와 왼쪽·오른쪽 한계에 같은 열 오프셋을 더합니다.
그 결과 모든 새의 이동 구간 길이와 왕복 위상이 같아지고, 같은 갱신에서 함께 방향을 바꿉니다.
서로 다른 화면 가장자리에서 개별적으로 튕겨 편대가 흐트러지는 것을 방지합니다.
가로 간격은 130px, 세로 간격은 72px입니다.
800px 캔버스와 1600px 캔버스의 반복 왕복을 테스트했으며,
더 좁은 캔버스에서는 열 간격이 줄어들지만 원래 실행 크기인 1600 × 600을 기준으로 배치했습니다.

## 6. boy와 숫자 표시 위에 높이 배치

boy의 기본 중심 높이는 90px이고 서 있는 스프라이트의 위쪽은 140px입니다.
시간 글꼴은 16px이며 메시지 중심은 boy보다 50px 위이므로 메시지의 위쪽은 148px입니다.
`Boy.visual_top`은 두 값 중 높은 값을 반환합니다.

화면 중간의 `3M`, `6M` 같은 빨간 거리 숫자도 높이 기준에 포함합니다.
`ruler.png`는 높이 100px이고, 숫자는 이미지 위쪽에서 50px 아래에 시작합니다.
현재 이미지 중심이 y=350이므로 숫자 상단은 y=350입니다.

```text
reference_top = max(boy.visual_top, grass.label_top) = 350
draw_height = 170 * (70 / 182) ≈ 65.3846
lower_row_y = reference_top + 16 + draw_height / 2 ≈ 398.6923
upper_row_y = lower_row_y + 72 ≈ 470.6923
```

아래 줄의 사각 영역 하단은 y=366으로 거리 숫자보다 16px 위이고,
위 줄의 상단은 약 y=503.38로 600px 화면 안에 들어옵니다.
이 기준은 이미지의 투명 여백까지 포함하므로 실제 색칠된 새도 표시를 가리지 않습니다.
boy는 수평으로만 이동하므로 편대의 높이를 매 프레임 따라 움직일 필요가 없습니다.

## 7. 기존 게임과 연결 및 검증

`play_mode.init()`에서 이미지 한 번으로 새 10마리를 만들고 기존 월드 1번 레이어에 등록합니다.
기존 `game_world.update()`와 `render()`가 새도 함께 처리합니다.
`finish()`는 월드를 비우고 새 목록도 초기화합니다.
`main()`은 `finally`에서 캔버스를 닫습니다.

자동 테스트 13개로 원본 크기·클립, 마지막 행 정렬, 좌우 반전, 날갯짓 주기,
30km/h 이동, 정확한 경계 및 초과 거리 반사, 매우 긴 이동,
30·60·144 FPS 일치, 단일 텍스처·10마리, 편대·화면 범위,
boy·숫자 위 높이, 모드 종료, 현재 프레임 시간 전달을 확인했습니다.

또한 `tools/check_render.py`로 실제 SDL 이미지·폰트·렌더러를 사용해 양방향 비행과 전체 포즈를 출력했습니다.
출력 이미지를 확인하여 잘린 날개, 빈 포즈, 숫자와 겹침이 없음을 검토했습니다.
